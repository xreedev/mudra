Say it your way — without handing your phone to someone else.

MUDRA+ lets Deaf and hard-of-hearing users make and take phone calls on their own. Sign into the camera, confirm the sentence, and the phone speaks it into the call. Hand tracking, sentence generation, transcription and memory all run on the device — no server, no API key, no account.

The pain point

A Deaf person cannot independently do the most mundane thing in adult life: make a phone call.

01

The pharmacy only takes phone orders

The clinic "will call you back". The delivery driver is outside, calling. Everyday logistics assume a voice on the line.

02

Relay services cost independence

Scheduling, a third human on the line, and telling a stranger your prescription and your address. Privacy traded for access.

03

In an emergency it isn't an inconvenience

At 2 a.m., with no signal and no interpreter, the gap between signing and speech is the gap between getting an ambulance and not.

The core idea: lean on the detection model as little as possible

Most systems ask one big model to recognise a huge vocabulary and produce fluent English. That model becomes the single point of failure, needs retraining to learn anything new, and is exactly what breaks on a handheld camera. MUDRA+ inverts it — recognition is the smallest, dumbest part of the system.

MOVE 1

Geometry, not inference

21 hand landmarks, normalised around the wrist, expanded to a 72-dimension vector and ranked by RMS Euclidean distance. A classifier's output layer is hard-wired to its training vocabulary — this isn't, so users add their own signs at runtime.

MOVE 2

The LLM does the language

ME NEED METFORMIN ONE STRIP has no articles, tense or politeness. Recognition only has to answer "which sign is this?" — a far easier question — so accuracy requirements drop dramatically. That's why a tiny vocabulary can drive a real conversation.

MOVE 3

Memory removes the model

People repeat themselves: same medicine, same pharmacy, every month. Once ME|TEA|HOT is confirmed, it never needs a model again. The app gets faster the more you use it — the opposite of how ML products usually age.

The safety net across all three: nothing is ever spoken until you confirm it. The LLM's output is a candidate, not an action — which makes the confirmation gate the hallucination guard and the misrecognition guard at the same time. For emergency phrases the model only structures the message; the number and address come from validated fields, never invented.

A productivity tool, not a demo

MUDRA+ isn't a translator you marvel at once. It's autofill for your own voice.

How it runs

Every box below executes on the phone. The only network traffic the app can make is a LAN socket to a second phone you pair with yourself.

Getting the voice into the call

Android gives third-party apps no public API to inject audio into a cellular call. This is the hardest constraint in the product, so two routes are built rather than one:

  • Acoustic coupling — put the call on speakerphone and let the phone's own microphone, already open for the call, pick up the TTS output. Works on any carrier call with no server. Cost: audio quality, and echo cancellation can fight it.
  • Local relay — two phones discover each other over zeroconf/mDNS and hold a TCP socket. The signer's phone sends text; the receiving phone speaks it and streams a transcript back. No cloud telephony, no per-minute bill, no third party listening.

Technical notes

Recognition

  • Features. Landmarks are normalised around the wrist — translation- and scale-invariant — then expanded into a 72-dimension vector using the identical transform the snapshot trainer used, so bundled and user-recorded signs are directly comparable.
  • Matching. Rank templates by RMS Euclidean distance; emit UNKNOWN above threshold 0.42. An honest UNKNOWN beats a confident wrong gloss on an emergency call.
  • Capture quality gate. Hand present, close enough (handSpread), steady (maxJitter) — failures return plain language ("Move your hand closer", "Hold your hand steady") instead of silently storing a bad template.
  • Hold-to-confirm. A progress ring fills over ~1 s, with a cooldown that forces a sign to visibly re-form, so one held hand can't spam a gloss.
  • Detection zone. On a call, only a hand held at sign height near the guide ring counts — reaching for the phone isn't a sign.
  • User signs override bundled ones. Persisted as app-private JSON with atomic temp-file-then-swap writes, a pub-sub so other mounted screens reload live, and a serialised save queue so concurrent captures can't corrupt the store.

Sentence generation

  • LlmProvider is a one-method interface; LocalLlmProvider implements it over llama.rn. The app ships local-only by design.
  • Prompts request multiple candidates, because glosses are genuinely ambiguous — ARRIVED HOME means different things from a customer and a driver. The user picks; the app doesn't guess for them.
  • The call's conversation history is fed back as context, so replies fit what was just said.
  • Sentence memory records which candidate was picked per exact gloss sequence and resurfaces it ahead of fresh guesses. Picking a different sentence later adds an option rather than replacing it. Once a sequence has enough remembered, the LLM is never called for it again.

Translation memory layer

The same engine implemented twice — Kotlin/Android (Room + SQLite) and TypeScript (any RN SQLite binding via a six-line adapter). Both standalone, dependency-free, independently tested.

flat1 k → 50 k corpus
~2.1 µsexact lookup, TypeScript
46tests across both ports
  • Exact hits are O(1). Kotlin hashes the token characters in place (FNV-1a, no joined key string, zero allocation) into an open-addressing table. Collisions are resolved by verifying tokens, never by trusting the hash.
  • Near hits are cheap. An IDF-weighted inverted index narrows the corpus to 48 candidates, then scores them 0.45·weightedJaccard + 0.25·queryCoverage + 0.30·lcsRatio. The LCS term makes sign order count; IDF makes METFORMIN outweigh ME. Unknown glosses get single-edit repair (METFORMIM → METFORMIN).
  • Writes never block a read. Ids are assigned in RAM, so a confirmed phrase is queryable before SQLite has heard of it; persistence is write-behind.
  • It degrades instead of failing. A corrupt or full database flips the layer to memory-only, counts the failure and tells the app. Warm-up skips corrupt rows rather than failing start-up. Bad input from a glitching recogniser is a returned value, never an exception.
  • Bounded. 20 000 memories, then the least-used unpinned entry is evicted. Pinned emergency phrases are never evicted; a fully pinned corpus refuses a write rather than dropping one.

Call and audio

  • Outgoing: confirmed text → react-native-tts → speaker → the call, or → TCP relay → the receiving phone speaks it.
  • Incoming: mic → PCM stream → whisper.rn → on-screen transcript. The receive mic pauses while the phone is speaking, so the app doesn't transcribe its own voice back into the conversation.
  • Discovery: zeroconf/mDNS advertise-and-browse, TCP socket for the session, and the UI shows the real socket state rather than a decorative "connected".

The app

React Native 0.76 (bare), TypeScript strict, React Navigation native stack, and a tokenised design system — screens never hard-code a colour or a spacing value, so dark mode follows the system setting for free. Icons are a hand-written 24 px SVG set, not an icon font. Icon-only controls always carry an accessibility label; nothing interactive is under 44 pt. Screens: Home, Call, Receive, Memory, Add custom sign.

Running on Snapdragon 8 Elite Gen 5

The target device isn't incidental — several choices exist because of it.

A 3B model fits comfortably

Q4_K_M at ~2.0 GB sits well inside the iQOO 15's RAM, which is why the app bundles a 3B rather than the 1.5B originally planned. llama.cpp runs it on ARM NEON/dotprod kernels with GPU layer offload.

ADPF performance hints

The memory layer opens a PerformanceHintManager session per lookup thread, declaring a ~2 ms target and reporting actual duration. On a big.LITTLE flagship a microsecond-scale burst otherwise finishes on an efficiency core before a reactive governor notices it should have ramped.

Core-aware threading

The write-behind thread runs at THREAD_PRIORITY_BACKGROUND so SQLite never competes with the camera pipeline for prime cores. Room opens in WAL with synchronous = NORMAL on its own executor.

Thermals are the real budget

Continuous camera plus continuous LLM is what heats a phone. The architecture minimises how often the LLM runs at all — which is exactly what the memory layer is for. A repeated phrase costs a hash lookup, not a 3B forward pass.

Two honest caveats. The LLM runs on CPU/GPU, not the Hexagon NPU — llama.cpp has no QNN backend in this configuration, and we'd rather say so than imply an acceleration path we didn't take. And OriginOS "performance mode" toggles are not app-accessible APIs; ADPF is the supported route to the same scheduler, and the code doesn't pretend otherwise.

Privacy

  • No cloud inference. No API keys. No accounts. No analytics.
  • Prescriptions, addresses and emergency details never leave the phone.
  • The memory layer has no network code, no permissions and no exported components, and never logs translation text.
  • Custom signs and remembered sentences live in app-private storage; "clear all" actually clears.
  • The only network traffic possible is a LAN socket to a second phone you pair yourself.

The demo runs in airplane mode. That isn't a stunt — it's the architecture.
